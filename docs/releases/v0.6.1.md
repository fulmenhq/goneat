# Goneat v0.6.1 — Rust Formatting, Fail-Closed Assessments, and Linked Worktrees

**Release Date**: 2026-09-28
**Status**: Stable

## TL;DR

- **Rust formatting is checked**: `goneat format` and `goneat assess` now run `cargo fmt` for Cargo projects. Earlier versions did not check Rust formatting.
- **Assessments fail closed**: clippy and biome failures, an invalid `.goneat/assess.yaml`, and unknown category names now fail instead of passing silently. Git hooks now fail when a category errors, as a direct `goneat assess` already did. cargo-audit runs that produce no report are now diagnosed, but security scanner errors are still only logged (see Known Limitations).
- **Lint and security run on more machines**: lint no longer disappears without golangci-lint, and security no longer requires gosec or govulncheck.
- **Linked Git worktrees** are read correctly by repo-status, maturity, dates and `version propagate`.
- **Clippy configuration** via `lint.rust.clippy` in `.goneat/assess.yaml`.
- **Minimum Go for building from source is now 1.26.** Release binaries are unaffected.

If you rely on `goneat assess` for Rust projects, re-run it after upgrading: earlier versions did not check Rust formatting and could report lint as passing when Cargo failed to run.

## Behavior Changes

These changes can turn a previously passing run or hook into a failing one. In each case the earlier pass was not based on a completed check.

- **Git hooks now fail when an assessment category errors** (tool crash, invalid `.goneat/assess.yaml`, missing required Rust tooling), matching direct `goneat assess`. `--fail-on` thresholds for completed findings are unchanged. Fix by correcting the config, installing the tool, or setting `format.rust.enabled: false` in the project `.goneat.yaml` where Rust formatting is intentionally disabled.
- **Missing cargo or rustfmt fails** an assessment with Rust in scope, unless `format.rust.enabled: false` is set.
- **Clippy with error diagnostics reports category status `error`** instead of `issues`.
- **An invalid `.goneat/assess.yaml` fails** the lint and typecheck categories, naming the file and offending keys, instead of running with defaults. A missing file still means defaults.
- **Unknown assessment category names now fail instead of being ignored.** The error lists the valid names, and no category in the list runs.
- **Lint runs its other tools without golangci-lint.** Only Go lint is skipped, with a note in the report.
- **A requested category that cannot run on this machine is reported as `skipped` with a reason**, rather than left out of the report.

Because checks that were previously skipped now run, repositories may see existing findings for the first time, such as YAML or workflow lint findings on machines without golangci-lint. Correct the findings, or adjust your lint policy if the rule does not fit the repository.

## What Changed

### Rust

- **Formatting**: `goneat format` and `goneat assess --categories format` run `cargo fmt --all` for the containing Cargo workspace; check mode reports one issue per unformatted file. Configure with `format.rust.enabled` and `format.rust.toolchain` in `.goneat.yaml`.
- **Clippy fails closed**: a non-zero Cargo exit (manifest or dependency errors, build-script failures, missing toolchain or target) fails the lint category with Cargo's stderr tail. Diagnostics parsed before the failure are kept. goneat disables rustup auto-install for these runs.
- **Clippy configuration**: `lint.rust.clippy` sets `toolchain`, `all_targets`, `all_features`, `features`, `no_default_features`, `locked`, `packages` and `targets` (one run per target triple, duplicate findings merged). Defaults are unchanged.

### Assessment reliability

- **biome** treats a timeout, a killed process, or a non-zero exit the report does not explain as an error, which fails the category.
- **cargo-audit** runs are checked the same way: output without a vulnerabilities section, or a non-zero exit without advisories, is reported as a scanner error. Like other security scanner errors, it is logged and does not fail the category.
- **yamllint** strict-mode warnings (exit 2) are reported as findings. Any other failure, including stderr output or unparsable output, fails the category.
- **Missing shfmt** skips shell format lint, like shellcheck, actionlint and checkmake.
- **Security** runs whichever applicable scanner is installed, including cargo-audit and cargo-deny for Cargo projects, and is skipped with a reason when none applies.
- **`goneat hooks validate`** warns about unknown category names in `.goneat/hooks.yaml`.
- **JSON output** adds `reason` (skipped categories) and `notes` (parts of a category that did not run) to category results.

### Configuration

- **`.goneat/assess.yaml`** schema rejects unknown top-level keys. The loader warns once per run about each unknown key and ignores it, keeping the other sections.

### Linked Git worktrees

Repository state is read correctly in worktrees created with `git worktree add` (attached or detached HEAD). Previously every tracked file could appear uncommitted, or status failed with "object not found".

- repo-status and release-phase maturity report a failure to read git state as a high `git-status-error` finding.
- `dates` runs its impossible-chronology check in linked worktrees and reports when it cannot.
- `version propagate` no longer blocks a clean linked worktree as dirty.

### Build and tooling

- `go.mod` declares `go 1.26.0`, required by `golang.org/x/crypto` v0.56.0.
- Recommended tool pins: Go 1.26.6, cargo-deny 0.20.2, cargo-audit 0.22.2.
- `make license-audit` and `make license-inventory` fail when `go-licenses` errors or returns an empty inventory.

## Security

- **go-git** 5.19.1 → 5.19.2 and **go-billy** 5.9.0 → 5.9.1: GO-2026-6213 (worktree symlink following), GO-2026-6214 (ref-name path traversal).
- **golang.org/x/crypto** 0.54.0 → 0.56.0: GO-2026-6354, GO-2026-6355 (SSH denial of service).
- Module-graph advisories in grpc, oras-go, x/mod, OpenTelemetry and klauspost/compress are resolved by the dependency refresh (opa 1.20.2, x/mod 0.41.0, x/sync 0.23.0, x/text 0.42.0, testify 1.12.1).

Release verification, built with Go 1.26.6:

- `govulncheck ./...`: no vulnerabilities in goneat's code or imported packages. One required-module advisory, GO-2026-5932 (the deprecated `golang.org/x/crypto/openpgp` package), is not imported and has no fix.
- `goneat dependencies --vuln`: 186 packages, 0 policy violations. The four findings (GHSA-6v2p-p543-phr9, GHSA-6wxm-mpqj-6jpf, GO-2026-5320, GO-2026-5932) are in modules that appear only in the module graph and are not needed by the build (`go mod why -m`), or, for GO-2026-5932, not imported.
- `goneat dependencies --licenses --cooling`: 71 dependencies, pass. The MPL-2.0 exception for `github.com/cyphar/filepath-securejoin` v0.7.0 remains in effect until 2027-03-31.

## Upgrading

### Building from source

Building from source or with `go install` requires **Go 1.26 or later**. Release binaries are unaffected.

### Rust projects

A top-level `rust:` block in `.goneat/assess.yaml` was never read and is now reported as ignored. Move the settings to their real homes:

```yaml
# .goneat/assess.yaml
version: 1
lint:
  rust:
    clippy:
      enabled: true
      all_targets: true
      locked: true
      # toolchain: stable
      # targets: [x86_64-unknown-linux-gnu]
```

```yaml
# .goneat.yaml
format:
  rust:
    enabled: true        # set false to opt out of Rust formatting checks
    # toolchain: stable
```

A top-level `format:` block in `.goneat/assess.yaml` was also never read. Formatter options belong in the `format:` block of the project `.goneat.yaml`, and path exclusions in `.goneatignore`.

### Hooks

Run `goneat hooks validate` to catch misspelled category names before they fail a commit or push.

## Known Limitations

- Security adapter execution errors are reported in logs but do not fail the category.
- A pre-commit that touches no Rust files still runs clippy project-wide. Scoping it to relevant files is planned.
