# Goneat v0.5.15 - Formatter Reliability and Toolchain Maintenance

**Release Date**: 2026-07-28
**Status**: Stable

## TL;DR

- **Standalone formatting now fails closed when a required external formatter is unavailable**. A selected Python file no longer produces a successful `goneat format` result when Ruff is missing.
- **Tool upgrade verification checks the binary that remains active after installation**. Go-tool upgrades now detect PATH shadowing, preserve versions for binaries discovered outside PATH, and verify the active binary against configured policy.
- **Go license tooling is pinned to v2 everywhere**. Make, CI, doctor defaults, repository policy, and user documentation now install `github.com/google/go-licenses/v2@v2.0.1`.
- **Direct, security-sensitive, resolver, and Unicode dependencies are refreshed** while the public `go 1.25.0` module floor remains unchanged.
- **Foundation tool recommendations are current** without raising minimum versions or changing the CI runner image.
- **Tool configuration has one clear runtime source of truth**. `.goneat/tools.yaml` remains the explicit repository policy, while embedded foundation defaults are used only by `goneat doctor tools init`.

## What Changed

### Formatting Fails Closed When Coverage Is Missing

`goneat format` now preflights the external formatters required by the selected files. If a required formatter is unavailable, the command reports tool unavailability and exits unsuccessfully instead of silently completing with incomplete coverage.

Formatting results now distinguish:

- files that need formatting;
- unavailable tools;
- tool execution failures; and
- file I/O failures.

The JSON result remains schema-compatible and includes actionable diagnostics. Canonical extension mapping ensures equivalent file types select the same formatter.

`goneat assess` continues to treat unavailable optional language tools as skipped coverage. For standalone formatting, `--ignore-missing-tools` is the explicit degradation path when finalizer-only processing is intentional.

### Doctor Upgrade and Version Verification

Go-tool detection now uses each configured CLI version probe before falling back to embedded Go build metadata. This avoids build metadata bypassing a tool's configured version behavior.

Upgrade verification also:

- retains version information for Go binaries discovered outside PATH;
- re-resolves the active binary after installation;
- requires that active binary to satisfy configured minimum and recommended-version policy; and
- reports when another binary on PATH shadows the newly installed version.

These checks prevent a successful installer exit from being mistaken for a successful upgrade when the shell would still execute an older binary.

### go-licenses v2 Install Surfaces

All maintained installation surfaces now pin:

```text
github.com/google/go-licenses/v2@v2.0.1
```

This includes Make targets, license-audit CI, active doctor configuration, embedded initialization defaults, and user documentation. Regression coverage protects both the exact package path and v2 tool-name inference.

An existing v1 binary already earlier on PATH is not automatically replaced. Reinstall the pinned command and confirm PATH order if doctor still reports v1:

```bash
go install github.com/google/go-licenses/v2@v2.0.1
```

### Tool Configuration Cleanup

The deprecated internal doctor defaults blob and its unused compatibility helpers have been removed. Runtime behavior remains explicit:

- `config/tools/foundation-tools-defaults.yaml` is embedded for `goneat doctor tools init`;
- `.goneat/tools.yaml` is the repository runtime source of truth; and
- no hidden defaults are merged into an existing repository policy.

This is a table-alignment update; the pre-existing East Asian-width box-rendering limitation is unchanged.

## Syft Security Cooling Exception

Syft 1.50.0 is intentionally recommended before the normal cooling window because that exact release remediates the named High advisory [GHSA-hrxh-6v49-42gf](https://github.com/advisories/GHSA-hrxh-6v49-42gf) in its scanner toolchain.

This is a narrow exception for a known High fixed in the exact release, not a general latest-version policy. It changes recommendation metadata only; it does not raise a minimum version or change the CI image.

The cooling exception was approved while Homebrew still provided Syft 1.49.0. Before release closeout, Homebrew's stable formula advanced to 1.50.0, so a current Homebrew install can now deliver the remediation. Local taps, caches, or installed binaries may still lag and should be verified. Neither Syft 1.50.0 nor Grype 0.116.0 is represented as vulnerability-clean; residual upstream binary findings may remain.

## Upgrade Notes

Most repositories need no configuration migration.

- Formatting pipelines that previously succeeded while Ruff or another required formatter was missing will now fail. Install the formatter, or use `--ignore-missing-tools` only when incomplete external-formatter coverage is intentional.
- Reinstall go-licenses with the pinned v2 command if an older binary remains active.
- Recommended tool-version changes are advisory unless your repository policy or upgrade workflow acts on them.
- Minimum tool versions and the public Go module floor are unchanged.

## Known Limitations

- govulncheck version output can currently be misread as the Go runtime version.
- Apple jq strings such as `jq-1.7.1-apple` are not currently accepted for semantic-version comparison.

Until the separate detector correction lands, the new govulncheck and jq recommendations should not be treated as operationally enforceable on affected hosts.
