# Goneat v0.5.16 - CI Tools Runner Adoption (fulmen-toolbox v0.5.1)

**Release Date**: 2026-08-03
**Status**: Stable

## TL;DR

- **CI containers pin `goneat-tools-runner-glibc:v0.5.1`**. Hosted CI leaves the v0.4.2 runner and adopts the fulmen-toolbox GA image that ships **ruff**, Go **1.26.5**, and the v0.5.0 tool/CVE refresh.
- **Closes the goneat ↔ fulmen-toolbox cycle for this train**: v0.5.15 made standalone `format` fail closed when a required external formatter is missing; toolbox v0.5.0/v0.5.1 put ruff in the full runners and embedded goneat v0.5.15; this cut makes goneat CI dogfood that runner.
- **Container-probe smoke checks `ruff --version`** so a future image without Python format/lint parity fails early.
- **No product CLI behavior change** beyond CI environment and documentation. Drop-in for v0.5.15 consumers of the binary/API.

## Why This Patch

### The cycle

1. **goneat v0.5.15** — standalone `goneat format` preflights external formatters and exits non-zero when one is unavailable (`--ignore-missing-tools` remains the explicit degradation path). `goneat assess` still reports skipped optional tools.
2. **fulmen-toolbox v0.5.0** — full runner images gain **ruff 0.15.22**, **zip**, Go **1.26.5**, and a broad fixable-CVE/tool sweep; runners embed **goneat v0.5.15**. Slim images still omit ruff by design.
3. **fulmen-toolbox v0.5.1** — release-pipeline hygiene only (manifest concurrency / GHCR throttle); **image contents match v0.5.0**. Pin the newer tag for current GA.
4. **goneat v0.5.16** — re-pin CI so dogfooding and consumer guidance agree with the released toolbox.

Without this pin, goneat CI would keep running on `:v0.4.2` (no ruff) while product behavior and toolbox images already assume the v0.5.x runner inventory.

## What Changed

### CI tools runner

`.github/workflows/ci.yml` container jobs (`build-test-lint`, `container-probe`, `bootstrap-probe`) now use:

```text
ghcr.io/fulmenhq/goneat-tools-runner-glibc:v0.5.1
```

Previous pin: `:v0.4.2`.

Notable runner content relative to v0.4.2 (from toolbox v0.5.0 notes; v0.5.1 is content-identical):

- **ruff** for Python format/lint parity with goneat dispatch
- **zip** beside existing `unzip`
- Go toolchain **1.26.5** and refreshed tool/OS pins from the toolbox sweep
- Embedded **goneat v0.5.15** inside the image

### Container probe

The container-probe job’s tool smoke list includes `ruff --version` so missing Python formatter inventory fails the probe instead of only failing later on Python repositories.

## Upgrade Notes

### Binary / library consumers

No API or default CLI policy change vs v0.5.15. Installing v0.5.16 is a normal patch upgrade.

### Repositories that copy goneat’s CI container pin

If your workflows hard-code:

```yaml
image: ghcr.io/fulmenhq/goneat-tools-runner-glibc:v0.4.2
```

plan to move to **`:v0.5.1`** (or a later toolbox GA) when you adopt fail-closed format behavior and/or Python format coverage. Full runners ship ruff; **slim** images deliberately do not — use a `-runner` variant or `--ignore-missing-tools` when formatters are intentionally absent.

### Host-local tool installs

No change to foundation recommended/minimum versions in this patch. Host installs of ruff remain independent of the CI image pin.

## Known Limitations

- Image pull size and cold-start may increase slightly vs v0.4.2 on first CI run after the pin change.
- Non-containerized jobs (`release.yml`, `license-audit.yml`) continue to use their existing Go setup actions; only the containerized CI jobs in `ci.yml` change image tags.
